CU-01
Iniciar sesión
Usuario de negocio
Precondiciones

El negocio ya fue dado de alta por el administrador de la plataforma y el usuario tiene su email y contraseña.

Flujo principal
  1. El usuario abre GestorPOS y carga su email y contraseña.
  2. El sistema valida las credenciales y confirma que el usuario está activo.
  3. El sistema inicia la sesión y muestra el panel Resumen del negocio.
Flujos alternativos
Credenciales inválidas: el sistema muestra un error y no inicia sesión. No existe la opción de "recuperar contraseña" por autoservicio — hay que contactar al administrador de la plataforma.
Resultado

Sesión iniciada, con acceso únicamente a los datos del negocio del usuario.

CU-02
Abrir caja
Usuario de negocio
Precondiciones

Sesión iniciada. No hay otra caja abierta en este momento.

Flujo principal
  1. El usuario entra a la sección Caja.
  2. Carga el monto inicial en efectivo con el que arranca el turno.
  3. Confirma la apertura.
  4. El sistema registra la caja como abierta desde ese momento.
Flujos alternativos
Ya hay una caja abierta: el sistema rechaza la apertura — primero hay que cerrar la caja existente.
Resultado

Queda una caja abierta, condición necesaria para poder registrar ventas.

CU-03
Registrar una venta
Usuario de negocio
Precondiciones

Sesión iniciada. Hay una caja abierta. Existe al menos un producto activo con stock.

Flujo principal
  1. El usuario entra a la sección Vender.
  2. Agrega uno o más productos al carrito, desde los más vendidos o buscándolos.
  3. Ajusta la cantidad de cada producto si hace falta.
  4. Opcionalmente carga el nombre y/o teléfono del cliente — si ya compró antes, el sistema sugiere sus datos y completa el que falte.
  5. Elige el medio de pago.
  6. Confirma el cobro.
  7. El sistema descuenta el stock de cada producto vendido, registra la venta y genera el ticket digital, con un botón para enviarlo por WhatsApp.
Flujos alternativos
No hay caja abierta: el sistema no permite cerrar la venta.
Stock insuficiente de algún producto: el sistema rechaza la venta e indica cuánto stock hay disponible.
Cliente sin nombre ni teléfono: la venta se completa igual, sin quedar asociada a ningún cliente.
Un producto cruza su stock mínimo al venderse: además de descontarse el stock, se dispara una notificación push de stock bajo (si está activada).
Resultado

Venta registrada, stock descontado, ticket generado y listo para enviar por WhatsApp.

CU-04
Cerrar caja
Usuario de negocio
Precondiciones

Hay una caja abierta.

Flujo principal
  1. El usuario entra a la sección Caja y elige cerrarla.
  2. Cuenta el efectivo físico y lo carga en el sistema.
  3. El sistema calcula el efectivo esperado (monto de apertura + ventas en efectivo del período) y lo compara contra lo contado, mostrando la diferencia.
  4. El usuario confirma el cierre.
Flujos alternativos
Diferencia entre lo esperado y lo contado: el sistema la muestra igual (positiva o negativa) — no bloquea el cierre, es informativa.
Resultado

Caja cerrada, con el resumen de ventas por medio de pago del período y la diferencia de efectivo registrada.

CU-05
Dar de alta un producto
Usuario de negocio
Precondiciones

Sesión iniciada.

Flujo principal
  1. El usuario entra a Productos y elige agregar uno nuevo.
  2. Carga SKU, nombre, categoría (puede crear una nueva sin salir del formulario), precio, costo, stock inicial y stock mínimo.
  3. Guarda el producto.
Flujos alternativos
SKU ya usado en el negocio: el sistema rechaza el alta e indica que el código ya existe.
Resultado

Producto disponible en el catálogo, listo para venderse.

CU-06
Ajustar stock manualmente
Usuario de negocio
Precondiciones

El producto ya existe en el catálogo.

Flujo principal
  1. El usuario entra a Productos y elige ajustar stock de un producto.
  2. Carga la cantidad (positiva para sumar, negativa para restar) y el motivo (reposición, merma, corrección u otro).
  3. Confirma el ajuste.
  4. El sistema actualiza el stock y registra el movimiento con fecha, motivo y usuario.
Flujos alternativos
No se carga un motivo: el sistema no permite confirmar el ajuste.
El ajuste cruza el stock mínimo hacia abajo: se dispara la notificación push de stock bajo (si está activada).
Resultado

Stock actualizado y movimiento registrado en el historial.

CU-07
Importar catálogo desde Excel
Usuario de negocio
Precondiciones

El usuario tiene una planilla con las columnas SKU, Nombre, Categoría, Precio, Costo, Stock inicial y Stock mínimo (se puede descargar una plantilla vacía desde el sistema).

Flujo principal
  1. El usuario entra a Productos y elige importar desde Excel.
  2. Sube el archivo .xlsx completo.
  3. El sistema procesa cada fila: si el SKU no existe, da de alta el producto; si ya existe, actualiza sus datos (sin tocar el stock actual). Las categorías que no existan se crean solas.
  4. El sistema muestra un resumen del resultado, incluyendo las filas que no se pudieron procesar.
Flujos alternativos
Alguna fila tiene datos inválidos: esa fila se reporta como error, pero no interrumpe el procesamiento del resto del archivo.
Resultado

Catálogo actualizado en bloque, con detalle de qué se creó, qué se actualizó y qué falló.

CU-08
Actualizar precios masivamente
Usuario de negocio
Precondiciones

Existen productos activos en el catálogo.

Flujo principal
  1. El usuario entra a Productos y elige actualizar precios masivamente.
  2. Define un porcentaje de aumento o descuento, y opcionalmente lo limita a una sola categoría.
  3. Confirma la actualización.
  4. El sistema recalcula el precio de todos los productos alcanzados.
Resultado

Precios actualizados en bloque, sin tener que editar producto por producto.

CU-09
Consultar y editar un cliente
Usuario de negocio
Precondiciones

El cliente ya realizó al menos una compra dejando su teléfono (se da de alta solo).

Flujo principal
  1. El usuario entra a Clientes y busca por nombre o teléfono.
  2. Abre la ficha del cliente: ve cantidad de compras, total gastado, última compra e historial completo de ventas.
  3. Si hace falta, corrige el nombre o el teléfono y guarda.
Flujos alternativos
El teléfono nuevo ya lo usa otro cliente del negocio: el sistema rechaza el cambio.
Resultado

Datos del cliente al día, sin afectar el teléfono con el que se registraron sus ventas pasadas.

CU-10
Generar un reporte en PDF
Usuario de negocio
Precondiciones

Sesión iniciada.

Flujo principal
  1. El usuario entra a Reportes y elige la vista Ventas o Stock.
  2. Define los filtros que necesite (rango de fechas, búsqueda, solo stock bajo).
  3. Elige exportar a PDF.
  4. El sistema genera el archivo con el encabezado del negocio (incluyendo el logo, si tiene) y lo descarga.
Resultado

PDF descargado, listo para imprimir o compartir.

CU-11
Consultar movimientos de stock
Usuario de negocio
Precondiciones

Sesión iniciada.

Flujo principal
  1. El usuario entra a Reportes → Movimientos.
  2. Opcionalmente filtra por producto y/o rango de fechas.
  3. Revisa el listado: cada fila muestra el producto, la cantidad (a favor o en contra), el stock resultante, el motivo y quién hizo el movimiento.
Resultado

Trazabilidad completa de por qué el stock de un producto es el que es hoy.

CU-12
Activar notificaciones de stock bajo
Usuario de negocio
Precondiciones

El navegador del dispositivo soporta notificaciones push. En iPhone, GestorPOS debe estar instalado a la pantalla de inicio.

Flujo principal
  1. El usuario entra a Configuración → Negocio.
  2. Activa el interruptor "Notificaciones de stock bajo".
  3. El navegador pide permiso para mostrar notificaciones; el usuario lo acepta.
  4. El sistema guarda ese dispositivo como suscripto.
Flujos alternativos
El usuario rechaza el permiso del navegador: el interruptor vuelve a apagarse y el dispositivo no queda suscripto.
El dispositivo no soporta notificaciones push: el interruptor directamente no se muestra en Configuración.
Resultado

Ese dispositivo recibe un aviso apenas un producto del negocio cruza su stock mínimo.

CU-13
Dar de baja o eliminar una categoría / medio de pago
Usuario de negocio
Precondiciones

La categoría o el medio de pago existen y no son "Efectivo" (protegido).

Flujo principal
  1. El usuario entra a Configuración y elige la categoría o medio de pago.
  2. Elige darlo de baja (queda oculto, se puede reactivar) o eliminarlo definitivamente.
  3. Si elige eliminar, el sistema verifica que nunca se haya usado en ningún producto o venta.
  4. El sistema aplica el cambio.
Flujos alternativos
Se intenta eliminar algo que ya se usó: el sistema rechaza la eliminación y sugiere darlo de baja en su lugar.
Se intenta modificar "Efectivo": el sistema lo rechaza siempre, esté o no en uso.
Resultado

La categoría o medio de pago queda oculto (reactivable) o eliminado sin dejar registros huérfanos.

CU-14
Dar de alta un negocio nuevo
Administrador de plataforma
Precondiciones

Acceso al panel de administración interno con la clave correspondiente.

Flujo principal
  1. El administrador entra a la pantalla interna de alta de negocios.
  2. Carga el nombre del negocio y los datos del usuario administrador (email y contraseña) que va a usar ese negocio.
  3. Confirma el alta.
  4. El sistema crea el negocio, completamente aislado del resto, y el usuario queda listo para iniciar sesión.
  5. El administrador le entrega las credenciales al dueño del negocio.
Resultado

Negocio nuevo operativo en la plataforma, con su propio espacio de datos.
